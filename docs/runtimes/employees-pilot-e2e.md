## What the run found

- **Interactive Copilot hangs on `--model auto`.** The footer stays on `Loading: ... still waiting on extensions; ide`
  and the first prompt stays queued for 15+ minutes, with or without the hat plugin (a plain worker did the same).
  Without `--model`, or with a named model, the session loads in seconds. `--model auto` works only with `copilot -p`.
  Do not set `model: auto` in `runtimes.json`.
- **`set_copilot_permissions` rejected a good switch** while the footer still showed `Loading:` instead of the mode.
  It now accepts the closed menu plus a `Loading:` footer (`tests/test_zed.py`).
- **Review findings land wherever the reviewer writes the draft** (Copilot put it under `~/.copilot/session-state/...`,
  outside the profile). `finish --draft` records the path, so the fix session found it, but the file is not durable.
- **The rule's edge showed in `suggest`.** For the fix, `suggest --hat build` ranked Quill first (task familiarity 15
  vs 5) although Quill reviewing and then fixing would leave nobody to re-review in a two-person pilot. The design
  says the fix must go to the author here (design 3.6 note, Q1); `suggest` does not yet know that.
- Copilot's Assisted Permissions still asked for routine shell commands (`zed-review prep`, `git diff`), and Claude
  asked once to read outside the working directories. The watcher answers these by rule in live use.
